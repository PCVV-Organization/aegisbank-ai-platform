# v1.0 Performance and Resilience Evidence

## Bounded Performance Baseline

The canonical local runner is `scripts/performance_baseline.py`. It measures
health and one safe synthetic loan READ with 25 iterations by default. This is
an intentionally moderate baseline, not stress, spike, endurance, or capacity
testing. No cloud endpoint and no banking WRITE is exercised.

The output is JSON under `reports/` and contains p50, p95, p99, mean, error
count, and error rate for each journey. The run is `TESTED-LOCAL` only after
the command has been executed and the output retained for the release commit.

Observed on commit `8393d88` with 25 iterations per journey:

| Journey | p50 | p95 | p99 | Error rate |
|---|---:|---:|---:|---:|
| `/health/live` | 1.23 ms | 1.92 ms | 4.17 ms | 0% |
| `/api/v1/loans/LOAN-0001` | 2.32 ms | 3.00 ms | 7.55 ms | 0% |

## Resilience Acceptance

Existing canonical tests cover bounded retry, timeout, circuit breaker,
transactional outbox, idempotent consumer, and DLQ behavior:

| Failure mode | Acceptance evidence | Release rule |
|---|---|---|
| Dependency timeout | `ai/agent/tests/**/test_*timeout*` | bounded failure, no hanging request |
| Transient dependency error | reliability unit/integration tests | retry policy only, no unbounded loop |
| Persistent dependency error | circuit breaker tests | circuit opens and recovers deterministically |
| Poisoned message | `test_idempotent_consumer_dlq.py` | one DLQ event, no duplicate side effect |
| Outbox recovery | reliability E2E tests | pending event remains recoverable |

Any unexecuted Docker, Kubernetes, Functions-host, or cloud test remains
`CLOUD-PENDING` or `BLOCKED`; it is never inferred from a static contract.
