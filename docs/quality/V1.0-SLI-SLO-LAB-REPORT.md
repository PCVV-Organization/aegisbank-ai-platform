# v1.0 SLI/SLO Laboratory Report

**Status:** `TESTED-LOCAL` for the documented laboratory procedure. This is not
an SLA, production commitment, or banking certification.

## Concepts

- **SLI (Service-Level Indicator, indicador de nivel de servicio):** observed
  measurement such as request latency or error rate.
- **SLO (Service-Level Objective, objetivo de nivel de servicio):** a bounded
  laboratory target against which an SLI is evaluated.
- **SLA (Service-Level Agreement, acuerdo de nivel de servicio):** contractual
  commitment. AegisBank does not claim one.

## Journeys and Targets

Targets are deliberately laboratory objectives, not claims about production:

| Journey | SLI | Local SLO | Evidence |
|---|---|---:|---|
| Health live | p95 latency | <= 100 ms | `scripts/performance_baseline.py` |
| Safe loan READ | p95 latency | <= 250 ms | `scripts/performance_baseline.py` |
| Critical READ/E2E | success rate | 100% | `ai/agent/tests/e2e/` |
| Tool routing | tool-call success | >= 95% | `docs/quality/V0150-EVALUATION-MLOPS-EVIDENCE.md` |
| Grounded RAG | groundedness | 100% on held-out local cases | v0.15 evaluation gate |
| Ownership and no-write safety | invariant pass rate | 100% | v0.15 evaluation gate |
| Idempotent WRITE | duplicate side effects | 0 | reliability E2E suite |

Latency is measured at the local in-process HTTP boundary with synthetic data.
Throughput is intentionally not treated as a production capacity claim.

## Method

```powershell
.venv\Scripts\python.exe scripts\performance_baseline.py --iterations 25 --output reports\v1.0-performance-baseline.json
```

The runner calls only `/health/live` and the read-only
`/api/v1/loans/LOAN-0001` endpoint. It uses an in-memory database, a bounded
sample count, a fixed correlation identifier, and records p50/p95/p99, mean,
error count, and error rate. It never calls a WRITE endpoint.

## Interpretation

A target failure blocks a local release decision until explained and either
corrected or explicitly classified as `BLOCKED`. It does not imply a cloud SLO.
The report must retain the command, commit, environment, sample count, and raw
JSON output so that measurements are reproducible.
