# v1.0 Masters Notes

## From Components to Evidence

An enterprise AI portfolio is not proved by the number of services. It is
proved by traceable behavior: a request crosses deterministic policy, tools,
data, safety, reliability, and observability boundaries; tests exercise the
journey; and a report records what was actually observed.

## Performance Vocabulary

**Latency** is elapsed time for one operation. **Throughput** is completed work
per unit time. **Error rate** is failed requests divided by total requests.
Percentiles such as p95 and p99 show tail behavior that an average hides. A
small bounded baseline is useful for regression detection, but cannot establish
capacity or an SLA.

## Reliability Vocabulary

**Fault injection** intentionally simulates a dependency failure. **Retry** is
safe only when bounded and the operation is known to be retryable. A **circuit
breaker** stops repeated calls while a dependency is unhealthy. A
**transactional outbox** makes database state and event publication recoverable.
An **idempotent consumer** makes a replay produce no second side effect. A
**DLQ (Dead-Letter Queue, cola de mensajes fallidos)** isolates poison events.

## Security Vocabulary

**STRIDE** is a threat-modeling mnemonic for spoofing, tampering, repudiation,
information disclosure, denial of service, and elevation of privilege.
**Trust boundary** marks where data or authority changes ownership. HITL is
per-action human approval; HOTL is supervisory intervention such as a
kill-switch. Neither is delegated to an LLM.

## Portfolio Interpretation

`TESTED-LOCAL` means reproducibly executed against synthetic local components.
`CLOUD-PENDING` means the design boundary exists but no cloud execution is
claimed. `PROD-UNPROVEN` means production capacity, SLA, certification, and
regulatory conclusions are intentionally outside the evidence.
