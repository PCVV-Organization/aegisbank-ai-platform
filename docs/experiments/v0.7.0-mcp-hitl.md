# v0.7.0 MCP + Human-in-the-Loop

## Result

AegisBank now has one local MCP v2 server launched through `stdio`. The
official Python SDK is pinned to `mcp==2.1.1`; the client and server negotiate
MCP protocol `2026-07-28`.

The exposed tools are exactly:

- READ: `search_knowledge`, `get_my_loans`, `get_loan_details`,
  `get_next_installment`
- WRITE: `create_service_request`

The READ tools carry `readOnlyHint=true`. The WRITE carries
`readOnlyHint=false` and `destructiveHint=false`. These annotations are
metadata only and are not used for authorization.

## HITL Boundary

The host creates an immutable `ApprovalRequest` from the normalized proposal,
using the runtime `AgentContext` customer. The CLI displays the exact tool,
category, description, and customer. Only an explicit `y` changes a pending
request to `APPROVED` and permits MCP `tools/call`. Any other response is
denied. The MCP server verifies tool identity, customer ownership, approval
state, and exact arguments before calling the deterministic Core Banking tool.

`REJECTED`, altered arguments, an approval belonging to another customer,
missing approvals, and an `EXECUTED` approval perform no write. MCP failures are
returned as structured, sanitized error objects.

## Evidence

- v0.7 acceptance: 32 passed, including in-process protocol calls and stdio
  negotiation.
- CLI REJECT smoke: `REJECTED: no MCP WRITE executed`.
- CLI APPROVE smoke: exactly one synthetic `SR-000003` created.

No v0.5/v0.6 held-out datasets or historical metrics were modified. Reliability
controls remain deferred to v0.8.
