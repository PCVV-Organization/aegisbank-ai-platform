# Plan de recuperación v0.5 con Foundry Local

## Alcance

Completar exclusivamente `v0.5.0 — Grounded Generation & LLM Evaluation`
usando Foundry Local 0.10.3 y el modelo local cacheado `phi-4-mini`.

Quedan fuera Azure, Docker, Agent, MCP, HITL, tools, worktrees y v0.6.
El tráfico permitido es únicamente localhost.

## Situación inicial

- Git: `master` en `1e92a6223bc5a96890f8b0d7ca5be43cb7e35bc2`.
- Foundry Local: `0.10.3`.
- El puerto es dinámico y se obtiene de `foundry server status -o json`.
- `phi-4-mini` está cacheado en GPU.
- La smoke anterior falló por conexión rechazada; no existe reporte held-out.

## Cambios

1. Mantener `LLMProvider` provider-agnostic y corregir el adaptador para usar
   `chat.completions` compatible con Foundry Local, devolviendo únicamente el
   contenido textual y saneando fences JSON/BOM.
2. Resolver el endpoint desde el estado del daemon, con override local opcional,
   y producir errores sanitizados cuando el CLI o daemon no estén disponibles.
3. Añadir una operación `smoke` independiente que realice exactamente una
   llamada local y valide parsing/citas sin crear reportes held-out.
4. Mantener la evaluación de seis casos protegida contra sobreescritura y cargar
   el corpus completo para conservar el caso de versión superseded.
5. Registrar provider, versión Foundry, alias, model IDs, prompt congelado,
   métricas y tráfico exclusivamente local.

## Secuencia de verificación

1. Ejecutar tests deterministas y Ruff sin inferencia.
2. Confirmar `foundry server status -o json`, `/v1/models` local y `phi-4-mini`.
3. Confirmar que el alias está cargado; si está cacheado pero no cargado,
   ejecutar `foundry model load phi-4-mini` como operación local previa, sin
   inferencia.
4. Ejecutar una única smoke. Si falla, detenerse sin held-out.
5. Confirmar que no existe `reports/generation-metrics.json` y ejecutar los seis
   casos held-out una sola vez.
6. Ejecutar regresiones v0.2/v0.3/v0.4/v0.5, Ruff, format, compileall, secret
   scan y `git diff --check`.
7. Documentar únicamente resultados observados y preparar revisión de staging.

## Criterio de parada

No crear commit hasta que smoke, held-out, métricas, regresiones, quality gates
y revisión de archivos pasen. No hacer push.
