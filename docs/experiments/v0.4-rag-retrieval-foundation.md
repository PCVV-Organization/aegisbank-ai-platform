# v0.4 RAG Retrieval Foundation

## Problem

AegisBank needs a reproducible retrieval foundation before any RAG generator is
connected. The foundation must remain local and deterministic so that offline
metrics are stable across runs and can later be compared against external
configurations.

## Research Question

Can a purely local retrieval pipeline over a synthetic Spanish banking corpus
deliver reproducible Precision@k, Recall@k, MRR@k, and nDCG@k at top-5 for
direct, paraphrase, version-distinguishing, and out-of-domain queries, using
only TF-IDF plus TruncatedSVD/LSA and Reciprocal Rank Fusion?

## Hypothesis

**H1, registered before the first evaluation:** A hybrid retriever that
combines lexical TF-IDF with a local dense TF-IDF + TruncatedSVD/LSA signal
through Reciprocal Rank Fusion (`k = 60`) outperforms either component
alone on the frozen synthetic evaluation set.

The hypothesis will not be changed after metrics are observed.

## Corpus

Twelve frozen synthetic documents span six topics (créditos, cuotas,
comisiones, productos, reclamos, políticas). One document
(`creditos_producto_general`) has two versions to exercise version-aware
filtering. Each document declares `document_id`, `version`, `effective_from`,
`effective_to`, `status`, and `source`; only documents with `status = active`
and an open effective window are indexed.

The corpus-manifest fingerprint is recorded in
`data/corpus-manifest.json`.

## Chunking

Document bodies are split at sentence boundaries and packed to a maximum of
300 characters per chunk. Chunk IDs take the form
`chk_{document_id}__{version}__c{n:03d}_{digest12}` so every chunk is
identifiable, version-bound, and reproducible.

## Methods

Three retrievers share the `Retriever` interface:

- `lexical_tfidf` — word-level TF-IDF with sub-linear term frequency,
  lowercase, bigrams.
- `dense_local_lsa` — TF-IDF reduced with `TruncatedSVD(n_components=64,
  random_state=42)` plus L2 normalisation. **Not equivalent to Azure AI
  Search embeddings.**
- `hybrid_rrf` — Reciprocal Rank Fusion over the two rankings above with
  `k = 60`.

Version filtering happens before retrieval: only `status = active` and
within-window documents enter the chunk set.

## Evaluation

Eighteen frozen synthetic queries split across four categories:

- direct (q001-q007) — facts named in exactly one document;
- paraphrase (q008-q012) — same intent in different wording;
- version (q013-q015) — must select the active version or surface the
  replacement of an older version;
- out-of-domain (q016-q018) — no relevant chunk should appear.

For each query we compute Precision@5, Recall@5, MRR@5, and nDCG@5 against
the qrels in `data/qrels.json`. The `evaluate` command rewrites
`reports/retrieval-metrics.json` and `reports/retrieval-report.md`. Future
invocations become reproducibility checks.

## Frozen Results

The one-time evaluation was run after corpus, chunking, retrievers, qrels
and configuration were frozen. No parameters were changed afterward.

| Method | nDCG@5 | MRR@5 | Precision@5 | Recall@5 |
| --- | ---: | ---: | ---: | ---: |
| lexical_tfidf | 0.352323 | 0.532407 | 0.188889 | 0.351852 |
| dense_local_lsa | 0.352323 | 0.532407 | 0.188889 | 0.351852 |
| hybrid_rrf | 0.352323 | 0.532407 | 0.188889 | 0.351852 |

H1 is recorded as **not supported** by the observed metrics: the three
retrievers produce identical ranking order on this controlled synthetic
corpus because the local dense component inherits the lexical vocabulary
and the corpus is small. The hybrid fusion therefore cannot add
discriminating rank information beyond either component. This is an honest
result, not a manipulation: the experiment is reproducible by seed and any
later corpus change that introduces a paraphrastic gap should let the dense
component diverge from lexical. The metrics describe this controlled
behaviour and must not be presented as production thresholds.

## CLI

```powershell
.venv\Scripts\python.exe -m aegisbank_rag.cli index
.venv\Scripts\python.exe -m aegisbank_rag.cli search "<query>" --top-k 5
.venv\Scripts\python.exe -m aegisbank_rag.cli evaluate
```

## Limitations

- The corpus is small, hand-authored, fully synthetic, and Spanish only.
- TruncatedSVD/LSA cannot model out-of-vocabulary tokens and has weak
  paraphrase behaviour.
- Hybrid RRF weights are frozen. Tuning requires a new ADR.
- No Azure AI Search comparison is included; `v0.4` is a pure local baseline.
- Retrieval metrics on synthetic data do not predict real banking traffic.

## Threats to Validity

- Author bias in the corpus and qrels.
- Synthetic Latin American Spanish templates may not represent natural
  customer language.
- The query set is small (18) and unbalanced across categories.
- LSA captures only linear correlations of TF-IDF features.
- Hybrid fusion does not learn weights; it can over- or under-weight one
  ranker on categories where its ranking density differs.

## Conclusion

A frozen local retrieval foundation is in place. It is reproducible by seed,
version-aware, and produces the four canonical offline metrics for three
retrievers. Downstream consumers can swap the `Retriever` implementation
without changing the public contract. The foundation intentionally does not
use Azure AI Search, embeddings, LLMs, agents, MCP, HITL, or Docker; those
introductions belong to later, separately authorised milestones.

## Next Experiment

Any later comparison — Azure AI Search, modern embedders, re-rankers,
hybrid weight tuning — requires a new ADR, a new qrels set, and an explicit
milestone authorisation. This experiment does not start the agent, MCP, HITL,
messaging, or Azure workstreams.
