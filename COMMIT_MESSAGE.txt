feat(auth): persist staging sessions in secure cookies

Purpose
Allow authenticated browser sessions to survive reloads without exposing the
opaque session token to JavaScript storage, while preserving bearer support for
non-browser clients.

Changes
- set Secure HttpOnly SameSite=None session cookies on synthetic login
- add a readable CSRF cookie and enforce double-submit validation for cookie-backed POST requests
- accept cookie sessions for me, logout, and agent requests with credentialed allowlisted CORS
- restore the authenticated customer on frontend startup through /auth/me

Validation
- ruff check ai/agent/src/aegisbank_agent/api.py: PASS
- pytest ai/agent/tests/unit/api/test_customer_auth.py ai/agent/tests/unit/api/test_agent_api.py -q: PASS (10 tests)
- frontend pnpm format, lint, typecheck, test -- --run, and build: PASS

Remaining limits
- Cookie persistence requires the deployed frontend origin to remain in the
  API CORS allowlist; the session TTL remains 900 seconds.
