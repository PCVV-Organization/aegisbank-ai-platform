# v0.3 Intent Classification Baseline

## Problem

AegisBank needs an evidence-based starting point for routing synthetic Spanish
banking queries by intent. This experiment establishes a classical ML baseline;
it does not create a production classifier or authorize any banking action.

## Research Question

Can a TF-IDF plus Logistic Regression model classify five synthetic banking
intent categories usefully and reproducibly before any comparison with an LLM?

## Hypothesis

**H1, registered before final evaluation:** A TF-IDF plus Logistic Regression
pipeline will clearly outperform a trivial baseline in macro-F1 on synthetic
banking queries across five intent classes.

The hypothesis will not be changed after holdout metrics are observed.

## Dataset

The generator will create exactly 500 UTF-8 records from controlled synthetic
templates using generation version `1.0.0` and seed `42`. Each class will contain
25 template groups with four variations per group. No real logs, conversations,
customers, personal data, or private datasets are permitted.

The generated dataset contains 400 TRAIN and 100 HOLDOUT examples. Its SHA-256 is
`db250b5993e892610d29a2cc53bdafcff08d085df29deecf9a53515a13308664`.

## Taxonomy

The frozen labels are `informational`, `account_query`, `service_request`,
`sensitive_action`, and `unsupported`. `sensitive_action` only describes an
intent; it never authorizes execution.

## Methodology

The trivial floor is `DummyClassifier(strategy="most_frequent")`. The primary
model is one `sklearn.pipeline.Pipeline` containing word-level TF-IDF followed by
Logistic Regression. The configuration is fixed before holdout evaluation:

```text
TfidfVectorizer(lowercase=True, ngram_range=(1, 2), min_df=1,
                max_df=1.0, sublinear_tf=True, norm="l2",
                stop_words=None, token_pattern=r"(?u)\b\w\w+\b")
LogisticRegression(C=1.0, l1_ratio=0.0, solver="lbfgs",
                   max_iter=1000, tol=1e-4, random_state=42)
```

No search, tuning, calibration, or learned preprocessing outside the pipeline is
allowed in this milestone.

## Leakage Controls

All four variations from one `template_group_id` remain on the same side of the
train/holdout split and the same side of every CV fold. The vectorizer is fitted
inside each training fold. Holdout contains five groups per class and remains
unseen until configuration, metrics, tests, and CV behavior are frozen.

## Baseline

The frozen `most_frequent` DummyClassifier produced holdout accuracy `0.200000`
and macro-F1 `0.066667`. It establishes only a trivial floor.

## Model

The model is the fixed TF-IDF plus Logistic Regression pipeline above. It is a
reconstructible baseline, not a serialized or externally sourced model.

## Cross-validation Design

Cross-validation uses only the 400 TRAIN examples with
`StratifiedGroupKFold(n_splits=5, shuffle=True, random_state=42)` and
`template_group_id` as `groups`. Every fold must prove zero group intersection.

## Primary Metric

`macro_f1` is defined before evaluation because every class matters and balanced
behavior is more informative than accuracy alone. Secondary metrics are
accuracy, macro precision, macro recall, and weighted F1.

## Results

The one-time frozen holdout evaluation was run only after TRAIN-only CV, dataset
validation, pipeline tests, and configuration freeze. No parameters or templates
were changed afterward.

| Evaluation | Accuracy | Macro precision | Macro recall | Macro F1 | Weighted F1 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Dummy holdout | 0.200000 | 0.040000 | 0.200000 | 0.066667 | 0.066667 |
| Model CV mean | 0.997500 | 0.997647 | 0.997500 | 0.997498 | 0.997498 |
| Model CV std | 0.005000 | 0.004706 | 0.005000 | 0.005005 | 0.005005 |
| Model holdout | 1.000000 | 1.000000 | 1.000000 | 1.000000 | 1.000000 |

H1 is supported within this controlled synthetic experiment because model
macro-F1 clearly exceeds the trivial floor. The result cannot be generalized to
real language or production behavior.

## Error Analysis

Misclassified HOLDOUT count: `0`. There are therefore no example IDs, expected
labels, predicted labels, or synthetic texts to enumerate. This absence is itself
treated cautiously: shared class-level phrasing and balanced template generation
likely make the task easier than natural banking language. No model change was
made after observing holdout.

## Limitations

The experiment is intentionally small, synthetic, balanced, predominantly
Spanish, template-generated, and disconnected from production traffic. Even
perfect metrics would not establish production suitability.

## Threats to Validity

- Synthetic data may not represent natural user language.
- Template-generated language may expose generator artifacts.
- Balanced classes do not reflect real intent prevalence.
- The corpus is small.
- One language predominates.
- There is no production traffic or real customer behavior.
- Generator phrasing can make classes artificially separable.
- The banking domain and available actions are simplified.

## Conclusion

The classical pipeline greatly exceeded the trivial baseline under group-aware
synthetic evaluation, so it provides a useful reproducible reference for later
experiments. It does not demonstrate production suitability, real-customer
generalization, calibrated probabilities, or safety for financial decisions.

## Next Experiment

Any later comparison requires separate authorization and a new milestone. This
experiment does not start RAG, Transformers, LLMs, agents, or integration with
the Core Banking Mock.
