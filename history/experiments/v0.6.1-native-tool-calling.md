# v0.6.1 Native Tool Calling Acceptance

## Status

`ACCEPTED - NATIVE TOOL CALLING PLUMBING`

## Scope

This micro-milestone fixes and verifies the end-to-end structured tool-call
boundary after the v0.6 baseline. It does not reopen or rerun the frozen v0.6
held-out evaluation and does not start v0.7.

## Diagnosis

Foundry Local `0.10.3` with `phi-4-mini` was probed once using a trivial
read-only function and `tool_choice="required"`. The local response contained:

- `finish_reason=tool_calls`;
- one structured `message.tool_calls` item;
- a structured function name `get_my_loans`;
- JSON arguments as a string.

The model/runtime therefore supports structured tool calling. The orchestrator
preserves the assistant tool-call message, validates and executes the allowlist,
then sends a `role=tool` message with the original `tool_call_id`.

## Acceptance Evidence

New acceptance tests cover structured calls for `get_my_loans`,
`get_next_installment`, and `search_knowledge`, plus assistant-to-tool message
round-tripping and serializable results. Text such as `get_my_loans()` is never
parsed as a substitute for a structured call.

## Historical Metrics

The canonical offline report remains `ai/agent/reports/agent-metrics.json` (8
cases). The canonical live baseline remains
`ai/agent/reports/agent-live-metrics.json` (15 cases). Their differing metrics
are expected because they are different datasets and runs; neither report is
overwritten or reconciled artificially.

The v0.6 live baseline remains unchanged:

- tool selection accuracy: `0.266667`;
- tool input accuracy: `0.466667`;
- tool call success: `0.533333`;
- no-write compliance: `0.933333`;
- ownership enforcement: `1.0`;
- task completion proxy: `1.0`.

## Boundary

Only the four v0.6 read-only tools remain exposed. No WRITE tool, MCP, HITL,
Azure, Docker, or v0.7 capability is introduced.
