## 2. Nomenclature From Zero

| Term | Meaning | Why it matters here |
| --- | --- | --- |
| LLM | Large Language Model, or modelo grande de lenguaje | Generates or interprets language; it proposes, but must not authorize banking writes. |
| Prompting | Designing instructions, context, examples, and constraints for a model | Controls repeatability and quality of assistant responses. |
| RAG | Retrieval-Augmented Generation, or generación aumentada por recuperación | Retrieves authorized evidence before generation, reducing unsupported answers. |
| KB | Knowledge Base, or base de conocimiento | The governed collection from which RAG retrieves information. |
| Grounding | Anchoring an answer to trusted evidence | Makes an answer traceable and limits fabrication. |
| Chunking | Splitting documents into retrievable pieces | Affects retrieval precision and recall. |
| Embedding | Numeric representation of meaning in a vector | Enables semantic similarity search. |
| NLP | Natural Language Processing, or procesamiento de lenguaje natural | Covers classification, extraction, and language understanding. |
| Agent | Software that observes a goal, reasons with constraints, and uses tools | Adds controlled action beyond text generation. |
| Orchestration | Coordinating model calls, tools, state, and policies | Determines the execution flow and boundaries. |
| MCP | Model Context Protocol, a standard interface for AI applications and tools | Provides discoverable, typed tool contracts; it does not replace authorization. |
| Tool call | Structured invocation of a function or external capability | Must be validated and audited before execution. |
| HITL | Human-in-the-Loop, human approval inside the execution loop | Required here before the synthetic banking WRITE. |
| HOTL | Human-on-the-Loop, human supervision with intervention or escalation | Useful for critical operations, but less strict than per-action approval. |
| Guardrail | Rule or control that limits unsafe inputs, outputs, or actions | Prevents sensitive or unsupported behavior. |
| AgentOps | Operating discipline for agents: telemetry, quality, incidents, and lifecycle | Connects experiments to sustainable production operation. |
| MLOps | Practices for deploying, monitoring, and governing machine-learning models | Extends quality beyond notebooks into repeatable operations. |
| DevSecOps | Development and operations with security integrated continuously | Makes security and dependency checks part of delivery. |
| E2E | End-to-end test across the complete workflow | Demonstrates behavior across agent, MCP, HITL, and Core Banking. |
| SLA | Service Level Agreement, agreed service reliability/response target | Makes operational expectations measurable. |
| API | Application Programming Interface, a contract between software components | Connects the agent to services without embedding their internals. |
| RPA | Robotic Process Automation | Automates deterministic UI or legacy-system steps; it is not interchangeable with an API. |
| DDD | Domain-Driven Design | Models software around the business domain and its rules. |
| CI/CD | Continuous Integration / Continuous Delivery | Automates validation and controlled delivery. |
| AI-103 | Microsoft Azure AI Apps and Agents Developer Associate exam | Emphasizes Foundry, generative AI, agents, RAG, evaluation, safety, and oversight. |
| AI-200 | Microsoft Azure AI Cloud Developer Associate exam | Emphasizes containers, Azure data, messaging, Azure services, security, monitoring, and troubleshooting. |

## 3. Current Fit Against the Role

### Strong evidence already demonstrated

- Prompting and structured tool calling with Foundry Local and `phi-4-mini`.
- RAG corpus versioning, chunking, hybrid retrieval, grounding, provenance,
  and retrieval evaluation.
- LLM evaluation harnesses, acceptance tests, regression tests, and frozen
  historical metrics.
- Deterministic authorization and customer ownership boundaries.
- MCP v2 local `stdio` boundary with the official Python SDK.
- HITL approval with exact-argument binding, rejection, replay prevention, and
  one synthetic WRITE operation.
- Synthetic banking domain, API integration, structured errors, and extensive
  automated testing.
- ADRs and reproducible experiment reports.

### Partial evidence

- Guardrails exist for tool authorization and grounded answers, but a broader
  content safety and moderation control plane is not implemented.
- Observability exists as test/report evidence, but production-grade traces,
  dashboards, alerting, and incident runbooks are not yet demonstrated.
- MLOps/AI lifecycle concepts are documented, but CI/CD and deployment are not
  yet demonstrated in Azure.
- Agentic behavior is currently one agent and one local MCP server, not a
  production multi-agent platform. This is intentionally conservative.

### Gaps that prevent claiming complete role readiness

- Azure/Microsoft Foundry deployment, managed identity, role-based access
  control, private networking, quotas, scaling, and cost management.
- Container image lifecycle, Azure Container Registry, Azure Container Apps,
  AKS, revisions, and KEDA.
- Azure Cosmos DB, Azure Database for PostgreSQL/pgvector, and Azure Managed
  Redis vector or caching workloads.
- Azure Service Bus, Event Grid, dead-letter handling, Functions, and
  event-driven workflows.
- Production troubleshooting, distributed tracing, SLOs, and operational
  ownership with an SLA.
- AI-103 areas outside the current scope: computer vision, text analysis, and
  information extraction.
- A real employer process brief/SIPOC and business case with measurable value;
  the repository currently uses a synthetic educational case.

## 4. How We Continue

1. Keep `v0.7` closed and preserve its evidence. It proves MCP and mandatory
   HITL without pretending to be cloud production.
2. Request approval for the next bounded milestone. The safest next milestone
   is a local reliability and messaging laboratory: idempotency, bounded
   retries, circuit breaking, queue/event semantics, and audit/observability.
   Do not add Azure or Kubernetes yet.
3. After local reliability evidence, plan an explicit Azure milestone aligned
   to AI-200: containerization, one Azure hosting path, managed identity,
   monitoring, and one messaging service. Any paid resource requires explicit
   approval.
4. In parallel, study AI-103 through Foundry concepts: model selection,
   grounding/RAG, agents and tools, evaluation, safety, auditing, provenance,
   approval workflows, and tool-access controls.
5. Use the role profile as a learning rubric, not as permission to expand scope.
   Each new capability needs a requirement, test evidence, documentation, and
   an ADR only when it is an architectural decision.
